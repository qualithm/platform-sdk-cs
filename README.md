# Platform SDK Cs

[![CI](https://github.com/qualithm/platform-sdk-cs/actions/workflows/ci.yaml/badge.svg)](https://github.com/qualithm/platform-sdk-cs/actions/workflows/ci.yaml)
[![codecov](https://codecov.io/gh/qualithm/platform-sdk-cs/graph/badge.svg)](https://codecov.io/gh/qualithm/platform-sdk-cs)
[![NuGet](https://img.shields.io/nuget/v/Qualithm.Platform)](https://www.nuget.org/packages/Qualithm.Platform)

C# client for the Qualithm Platform API, generated from its OpenAPI spec. Every operation and type
comes from the spec the API serves, so the client changes when the API does.

## Features

- **Every management operation** — one typed `async` method per operation, grouped by resource
  (`DevicesApi`, `AutomationsApi`, …), with the spec's names
- **One error type** — every failure is a `PlatformException` carrying the API's stable `Code`
- **Configured from the environment** — `QUALITHM_API_TOKEN` and `QUALITHM_API_URL`
- **`net10.0`** — one class library on the current .NET LTS

## Installation

```bash
dotnet add package Qualithm.Platform
```

## Quick Start

Create an API token in the Qualithm app, on the team page under **API tokens**, then:

```csharp
using Qualithm.Platform;
using Qualithm.Platform.Api;

using var platform = new PlatformClient(token: "<your-api-token>");
var page = await platform.Api<DevicesApi>().ListDevicesAsync();

foreach (var device in page.Data.Items)
{
    Console.WriteLine(device.Name);
}
```

## Usage

### Configure the client

`PlatformClient` reads `QUALITHM_API_TOKEN` and `QUALITHM_API_URL` when you don't pass `token` or
`baseUrl`. The base URL defaults to the production API, `https://api.qualithm.com`. Create one
client and keep it for the life of your app: it owns the HTTP connection pool.

```csharp
using var platform = new PlatformClient(baseUrl: "https://api.qualithm.com");
```

### Call an operation

Each generated `…Api` class in `Qualithm.Platform.Api` is one resource group. `platform.Api<T>()`
returns it bound to your client, created once. Method names match the spec's `operationId`s. Every
response is the API's envelope, so the result is in `Data`:

```csharp
var automations = await platform.Api<AutomationsApi>().ListAutomationsAsync(page: 1, limit: 50);
```

### Error Handling

Every error response and failed request throws `PlatformException`. Branch on `Code`, never on
`Message`. A code this version doesn't know yet reads as `ApiErrorCode.UnknownDefaultOpenApi`. A
request that got no response has `Status` `0`:

```csharp
using Qualithm.Platform.Model;

try
{
    await platform.Api<DevicesApi>().GetDeviceAsync(deviceId);
}
catch (PlatformException e) when (e.Code == ApiErrorCode.NotFound)
{
    // the device doesn't exist, or isn't in this workspace
}
```

## API Reference

The operations and types are generated from the platform's OpenAPI spec, committed as
[`openapi.json`](openapi.json). Every public type carries `///` XML doc comments, which ship in the
package for the editor. CI builds the reference with docfx on every pull request into `main`:

```bash
dotnet tool restore
dotnet docfx docs/docfx.json --serve
```

## Development

Everything builds and tests on macOS, Linux or Windows with the .NET SDK `global.json` pins.
Regenerating the client needs [Docker](https://www.docker.com/).

```bash
git config core.hooksPath .githooks   # run the checks before each commit
dotnet restore --locked-mode
dotnet format                         # fix formatting
dotnet test
dotnet pack -c Release                # the .nupkg and .snupkg, in bin/Release
```

`.claude/rules/checks.md` lists the commands CI runs, and `.githooks/pre-commit` runs them.

### Regenerating

`src/Qualithm.Platform/Generated/` comes from `openapi.json` and the generator pinned in
`scripts/generate`. Never edit it by hand: CI regenerates it and fails on any difference. The
platform opens a pull request here with the new spec and the regenerated code whenever its API
changes. To regenerate by hand:

```bash
scripts/generate
```

The hand-written layer is `PlatformClient.cs` and `PlatformException.cs`. The generated code sits
outside the repo's checks, which hold only the hand-written layer:

- **Format and analyzers:** `scripts/generate` starts every generated file with
  `// <auto-generated/>`, which `dotnet format` and the .NET analyzers skip, and keeps the
  generator's nullable setting (`#nullable enable annotations`). `.editorconfig` silences the one
  compiler warning the generated code trips (`CS8073`), for `Generated/` only.
- **Coverage:** the test project passes `--coverlet-exclude-by-file "**/Generated/**/*.cs"` through
  `TestingPlatformCommandLineArguments`, so the 80% line gate measures the hand-written layer.
